# 数据模型与接口

## 一、数据模型

库内时间统一存 UTC，日期型字段（提测日期、计划发布日期、任务的四个计划/实际日期）一律以 **UTC 零点**存储，读写用 `YYYY-MM-DD`，避免时区换算差一天。

### users

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | String(cuid) | 主键 |
| username | String unique | 登录账号 |
| displayName | String | 姓名，看板上显示这个 |
| passwordHash | String | bcrypt，10 轮 |
| role | Role | `ADMIN` / `MEMBER`，默认 MEMBER |
| active | Boolean | 停用后无法登录，默认 true |

### versions

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | String(cuid) | 主键 |
| name | String unique | 版本号，如 `R25C14` |
| description | String? | 测试范围、发布批次等 |
| status | VersionStatus | `TESTING` / `RELEASED` / `ARCHIVED`，默认 TESTING |
| testStartDate | DateTime? | 提测日期 |
| plannedReleaseDate | DateTime? | 计划发布日期 |
| createdById | String | 创建人 |

### tasks

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | String(cuid) | 主键 |
| versionId | String | 所属版本，版本删除时级联删除 |
| title | String | 任务标题 |
| description | String? | 测试范围、前置条件等 |
| assigneeId | String? | 负责人，可空（未分配） |
| participants | User[] | 参与人，多对多（关联表 `_TaskParticipants`） |
| priority | Priority | `P0`/`P1`/`P2`/`P3`，默认 `P2` |
| status | TaskStatus | `TODO`/`IN_PROGRESS`/`BLOCKED`/`DONE`，默认 `TODO` |
| progress | Int | 手动填写 0-100 的整数 |
| plannedStartDate | DateTime? | 计划开始日期 |
| plannedEndDate | DateTime? | 计划结束日期，**逾期判断以它为准** |
| actualStartDate | DateTime? | 实际开始日期 |
| actualEndDate | DateTime? | 实际结束日期 |
| sortIndex | Int | 看板列内排序，越小越靠前 |
| completedAt | DateTime? | 状态首次变为已完成的时间 |
| deletedAt | DateTime? | 软删除标记，非 null 即已删除 |

索引：`(versionId, status, sortIndex)`、`(assigneeId)`、`(plannedEndDate)`、`(deletedAt)`。

> 首版曾有 `module`（模块，自由文本）和 `dueDate`（截止日期），已按需求移除：模块对应的数据库列直接删除；
> 「截止日期」的值在迁移时被搬到「计划结束日期」（`20261009152000_task_fields_rework`），不丢数据。
> 删成员时其名下任务的 `assigneeId` 置空、参与关系级联删除，任务本身保留。

### comments

`taskId` / `authorId` / `body` / `createdAt`。任务级联删除。

### activity_logs

| 字段 | 说明 |
| --- | --- |
| taskId / actorId | 哪条任务、谁操作的 |
| action | `TASK_CREATED` `TASK_UPDATED` `TASK_DELETED` `STATUS_CHANGED` `ASSIGNEE_CHANGED` `PARTICIPANTS_CHANGED` `PRIORITY_CHANGED` `DUE_DATE_CHANGED` `PROGRESS_CHANGED` `COMMENT_ADDED` |
| field | 变更字段名。`DUE_DATE_CHANGED` 靠它区分是四个日期里的哪一个（`plannedStartDate` / `plannedEndDate` / `actualStartDate` / `actualEndDate`）；`PARTICIPANTS_CHANGED` 的 from/to 存人名（拼音排序）而非 id，便于直接阅读 |
| fromValue / toValue | 变更前后的原始值（枚举原值、进度数字、日期字符串） |

## 二、接口一览

统一前缀 `/api`，除登录外都需要 `Authorization: Bearer <token>`。Swagger 文档：`/api/docs`。

### 认证 `/auth`

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/auth/login` | 账号密码登录，返回 `accessToken` + 用户信息 |
| GET | `/auth/me` | 当前登录用户 |
| POST | `/auth/password` | 修改自己的密码（校验原密码） |

### 成员 `/users`

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/users?includeInactive=` | 登录用户 | 成员列表（负责人下拉用） |
| POST | `/users` | 管理员 | 新增成员 |
| PATCH | `/users/:id` | 管理员 | 改姓名/角色/启用状态 |
| POST | `/users/:id/reset-password` | 管理员 | 重置密码 |
| DELETE | `/users/:id` | 管理员 | 删除成员（其任务负责人置空） |

### 版本 `/versions`

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/versions?status=&keyword=` | 登录用户 | 版本列表，含进度汇总 |
| POST | `/versions` | 登录用户 | 新建版本 |
| GET | `/versions/:id` | 登录用户 | 版本详情 |
| GET | `/versions/:id/summary` | 登录用户 | 进度汇总（平均进度 + 完成率 + 各状态计数） |
| PATCH | `/versions/:id` | 登录用户 | 编辑版本 |
| DELETE | `/versions/:id?force=` | 管理员 | 删除版本；有任务时必须 `force=true` |

### 任务

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/versions/:versionId/tasks` | 分页列表，支持 `status/assigneeId/participantId/priority/keyword/page/pageSize/sortBy/order` |
| GET | `/versions/:versionId/board` | 看板数据，该版本全部任务不分页 |
| POST | `/tasks` | 新建任务（body 带 `versionId`） |
| GET | `/tasks/my` | 我的待办（我负责或我参与、且未完成；返回 `isAssignee` 区分） |
| GET | `/tasks/:id` | 任务详情 |
| PATCH | `/tasks/:id` | 编辑任务（含 `participantIds` 整体替换） |
| PATCH | `/tasks/:id/status` | **拖拽专用**：`{ status, targetIndex }`，改状态并落到目标列指定位置 |
| POST | `/tasks/batch` | 批量改负责人/优先级/状态 |
| DELETE | `/tasks/:id` | 软删除（创建者或管理员） |

- `assigneeId=unassigned` 表示只看未分配。
- `progress` 只接受 0-100 的整数，传小数或越界值会返回 400。
- `sortBy` 可选 `sortIndex`（默认）/`createdAt`/`plannedEndDate`/`priority`/`progress`/`title`。

### 评论与日志

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/tasks/:taskId/comments` | 评论列表（升序） |
| POST | `/tasks/:taskId/comments` | 发表评论 |
| DELETE | `/comments/:id` | 删除评论（本人或管理员） |
| GET | `/tasks/:taskId/activities` | 操作日志时间线（倒序，最多 200 条） |

### 统计

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/stats/versions/:versionId` | 按状态/优先级/负责人聚合 |

### 导入导出

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/versions/:versionId/export` | 导出 xlsx（含「填写说明」sheet）；列为 标题/负责人/参与人/优先级/状态/进度/计划开始/计划结束/实际开始/实际结束/描述 |
| POST | `/versions/:versionId/import/preview` | 上传 xlsx（multipart，字段名 `file`），返回逐行校验结果，**不落库** |
| POST | `/versions/:versionId/import/confirm` | 确认导入预览通过的行；服务端会**重新校验**，不信任前端回传结果 |

导入规则：

- 必须有「标题」列，缺失则该行不导入（`errors`）。
- 优先级、状态无法识别 → 用默认值兜底（P2 / 未开始），只给警告。
- 负责人只能一个，按登录账号或姓名匹配，匹配不到 → 留空 + 警告。
- 参与人可多个，用「、」「,」「;」「/」或空格分隔；匹配不到的名字被忽略 + 警告；重复的自动去重。
- 状态为已完成时进度强制 100%；进度只接受整数，小数会四舍五入并提示。
- 四个日期支持 `YYYY-MM-DD`、`2026/10/20`、`2026年10月20日` 等写法，识别不了就留空 + 警告。
- 计划开始晚于计划结束、实际开始晚于实际结束时给出提示（不拦截）。
- 单个文件上限 5MB，单次最多 2000 行。
- 常见表头别名可识别：任务标题/指派给/执行人/参与人/协作人/完成度/截止日期/计划完成日期/备注 等。

### 实时通道

Socket.IO 命名空间 `/ws`，连接时通过 `auth: { token, versionId }` 鉴权并进房间，也可连上后发 `subscribe` 事件指定 `versionId`。

服务端广播事件：`task.created`、`task.updated`、`task.moved`、`task.deleted`、`task.batch-updated`、`comment.created`、`comment.deleted`。载荷里都带 `by`（操作人姓名）便于提示。

前端策略：**收到任何事件就重新拉取当前版本数据**，不做客户端增量合并——服务端算出的进度和排序才是唯一事实来源。

## 三、版本进度算法（`backend/src/versions/version-summary.ts`）

```
平均进度   = round( Σ clamp(task.progress, 0, 100) / 任务数 )
完成率     = round1( 已完成任务数 / 任务数 × 100 )
```

- 只统计 `deletedAt = null` 的任务。
- 任务数为 0 时两个值都是 0（不做除零）。
- 列表页用两次 `groupBy` 聚合批量算所有版本，不随版本数线性退化。

## 四、状态与进度联动（`backend/src/tasks/task.rules.ts`）

```
拖到 DONE      → progress = 100, completedAt = 已有值 ?? now
拖出 DONE      → progress 保持不变, completedAt = null
状态未变       → 两者都保持不变
手动改 progress → 不触发状态变化
```

进度入库前统一过 `normalizeProgress()`：非数字按 0、小数四舍五入、越界夹到 0-100。

## 五、逾期判断（`isOverdue`）

```
未完成 且 计划结束日期 < 今天  →  逾期
```

只看「计划结束日期」这一个字段，实际结束日期不参与判断。
