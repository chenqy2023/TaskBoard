# 需求确认结论

本文档记录开工前与需求方逐项确认的结果。后续如有变更，请在这里追加「变更记录」，不要直接改上面的结论，方便回溯当时为什么这么做。

## 一、总体定位

面向测试团队的**版本测试进度与任务管理**看板，多人共用一套数据，不是单机页面。

| 维度 | 结论 |
| --- | --- |
| 使用形态 | 多人访问的 Web 系统 |
| 后端 | TypeScript + NestJS + Prisma |
| 前端 | TypeScript + Vue3 + Vite + Ant Design Vue + Pinia |
| 数据库 | PostgreSQL 16-alpine |
| 部署 | 生产：CentOS 7 上 docker compose（nginx + api + postgres 三服务）<br>开发：本机 Windows 11，DB 走 Docker Desktop，前后端用 node 直接跑 |
| 镜像来源 | 直连官方镜像，镜像名/标签可在 `.env` 覆盖，便于以后切私有仓库 |
| 界面语言 | 中文 |
| 时区 | 展示用 `Asia/Shanghai`，库内统一存 UTC |

## 二、业务模型

**两层结构：版本 → 任务**，任务是最小工作单位（不做用例库）。

- 版本（Version）：版本号唯一，带提测日期、计划发布日期、状态（测试中／已发布／已归档）。
- 任务（Task）：归属某个版本，含标题、模块、负责人、优先级、状态、进度、截止日期、描述。
- 任务下挂评论与操作日志。

### 看板列（状态流转）

四列固定：**未开始 → 进行中 → 阻塞 → 已完成**

### 进度口径

- 任务进度由负责人**手动填写百分比**（0-100）。
- 版本进度 = 该版本全部未删除任务进度的**算术平均**（四舍五入为整数）。
- 同时展示**任务完成率** = 已完成任务数 / 总任务数（保留 1 位小数）。
- 两个口径并排显示，互相印证。

### 状态与进度的联动规则

| 操作 | 结果 |
| --- | --- |
| 拖到「已完成」 | 进度自动置 100%，记录完成时间 |
| 拖出「已完成」 | 保留原进度不清零，清空完成时间 |
| 手动把进度改成 100% | **不会**自动移动到「已完成」列（避免误操作） |

### 优先级与模块

- 优先级固定四档：P0 紧急 / P1 高 / P2 中 / P3 低。
- 模块为**自由文本**，输入时从该版本已有的模块中自动补全。不做字典维护，避免没人维护字典就写不进任务。

## 三、权限

账号密码登录（JWT），两种角色：

| 角色 | 能力 |
| --- | --- |
| 管理员 ADMIN | 管理成员、删除版本、删除任意任务、修改任意任务 |
| 成员 MEMBER | 新建任务、修改自己创建或自己负责的任务；不能删他人任务；不能进成员管理 |

补充约束：

- 管理员不能改自己的角色、不能停用或删除自己的账号。
- 系统必须始终保留至少一个启用的管理员。
- 成员可以查看全部版本与任务（看板对全员开放）。

## 四、功能范围

第一版包含（需求方全选）：

1. 登录 / 登出 / 修改密码，成员管理（管理员）
2. 版本管理：列表、新建、编辑、归档、删除，每行显示进度条
3. 看板：四列拖拽改状态、列内排序、新建/编辑/删除任务
4. 任务列表：表格视图、多条件筛选、排序、分页、行内改状态与负责人、批量修改
5. 评论 + 操作日志时间线
6. ECharts 统计：状态分布、优先级分布、各负责人任务数与平均进度、各模块完成情况
7. Excel/CSV 批量导入导出（导入先预览校验再落库）
8. 多人实时同步（Socket.IO 推送，看板自动刷新）

明确不做：

- 附件上传（需求方确认删除，因此也不需要对象存储和上传目录）
- 移动端适配（只保证桌面端 ≥1280px）
- 第三方登录、消息通知推送

## 五、交付节奏

分两阶段，先后核心再加分项：

- 阶段一（核心链路）：登录 → 版本 → 看板拖拽 → 进度汇总 → 任务列表筛选。可本地完整演示并验收。
- 阶段二（加分项）：评论/日志、统计图表、Excel 导入导出、实时同步。
- 阶段三（生产交付）：生产 compose、nginx 反代、关键单测、部署与冒烟文档。

## 六、测试要求

- 后端关键逻辑写单元测试（进度汇总、状态与进度联动、权限规则、导入行校验）。
- 不写 Playwright E2E，交付一份**手工冒烟清单**（见「部署与冒烟清单」）。
- 另提供接口级冒烟脚本 `scripts/api-smoke.py`，一条命令跑完 37 项检查。

## 七、开工时定下的默认决定

以下为实现方按「不惊吓用户 / 少配置」原则定的默认值，如不认可可以改：

1. 初始管理员账号密码由 `ADMIN_INITIAL_PASSWORD` 环境变量注入，仅在库中无用户时创建。
2. JWT 有效期 7 天，token 存 localStorage（便于开发期调试）。
3. 任务删除为**软删除**（`deletedAt`），操作日志与评论保留可追溯；版本删除为硬删除，且当版本下还有任务时必须显式带 `force=true`。
4. 操作日志自动记录：创建/删除任务、状态变更、负责人变更、优先级变更、截止日期变更、新增评论；**进度变动小于 5% 不记日志**，避免拖进度条刷满时间线。
5. Excel 列名固定为「标题/模块/负责人/优先级/状态/进度/截止日期/描述」，并容忍一些常见别名（如「任务标题」「指派给」「计划完成日期」）。
