# 部署与冒烟清单

## 一、本机开发环境

前提：Windows + Docker Desktop 已启动，Node.js 22。

```bash
# 1. 根目录准备环境变量
cp .env.example .env          # 首次执行，按需修改

# 2. 只起 PostgreSQL（若本机 5432 被占用，改 .env 里的 POSTGRES_PORT 与 DATABASE_URL）
docker compose --env-file .env -f docker/docker-compose.dev.yml up -d

# 3. 后端：装依赖 -> 建表 -> 造初始管理员 -> 起服务
cd backend
npm install
npx prisma migrate dev        # 本地开发用 dev，会生成迁移文件
npx prisma db seed            # 建初始管理员（幂等，重复执行安全）
npm run start:dev             # http://localhost:3000/api ，文档 /api/docs

# 4. 前端（另开一个终端）
cd frontend
npm install
npm run dev                   # http://localhost:5173
```

默认账号：`admin` / `Admin@123456`（来自 `.env` 的 `ADMIN_INITIAL_PASSWORD`）。

开发期前端通过 vite 代理把 `/api` 和 `/socket.io` 转发到 `localhost:3000`，不需要处理跨域。

常用命令：

| 命令 | 作用 |
| --- | --- |
| `npm run start:dev`（backend） | 后端热重载 |
| `npm run test`（backend） | 后端单元测试（51 项） |
| `python scripts/api-smoke.py` | 接口级冒烟（37 项），`--base` 可指向任意地址 |
| `python scripts/api-smoke.py --keep` | 保留测试数据，便于在界面上翻看 |
| `node scripts/ws-smoke.mjs <base>`（frontend 目录） | 实时通道冒烟（9 项），显式验证不降级为轮询 |
| `npm run typecheck`（frontend） | 前端类型检查 |
| `npm run build`（frontend） | 生产构建（含类型检查） |

## 二、生产部署（Linux 服务器 + Docker）

### 前置要求

1. Docker Engine ≥ 20.10，并已安装 **docker compose v2 插件**（`docker compose version` 能输出版本号）。
   本仓库只用 `name:` / `depends_on.condition` 这类 compose 2.3+ 的通用写法，
   不依赖更新版本的专有语法（已在 CentOS 7 内核 3.10 上实际部署验证）。
2. 需要 **compose ≥ v2.3**（compose 文件用了顶层 `name:` 字段）。
3. 服务器能拉取官方镜像，或已在 `.env` 里把 `IMAGE_POSTGRES` / `IMAGE_NGINX` 换成私有仓库地址。
4. 开放 `WEB_PORT`（默认 8080）。

### 部署步骤

```bash
# 1. 上传代码到服务器，进入仓库根目录
cp .env.example .env
vi .env
#   必须改：
#     JWT_SECRET=$(openssl rand -hex 32)
#     POSTGRES_PASSWORD=<强密码>
#     ADMIN_INITIAL_PASSWORD=<初始管理员密码>
#   按需改：
#     WEB_PORT=8080
#     DATABASE_URL 仅本地开发用，容器内由 compose 注入，可以不改

# 2. 构建并启动
docker compose --env-file .env -f docker/docker-compose.yml up -d --build

# 3. 看日志确认迁移与启动成功
docker compose --env-file .env -f docker/docker-compose.yml logs -f api
#   期望看到：执行数据库迁移 -> 检查并初始化管理员 -> 启动 API 服务

# 4. 访问 http://<服务器IP>:8080
```

`api` 容器启动时会自动依次执行 `prisma migrate deploy` 和 `prisma/seed.js`，两者都是幂等的，重启容器不会重复造数据。

### 日常运维

```bash
# 重启
docker compose --env-file .env -f docker/docker-compose.yml restart api

# 更新代码后重新部署（数据在命名卷 task_kanban_pg_data 里，不会丢）
git pull
docker compose --env-file .env -f docker/docker-compose.yml up -d --build

# 备份数据库
docker exec task-kanban-db pg_dump -U kanban task_kanban > backup_$(date +%F).sql

# 恢复
cat backup_2026-10-09.sql | docker exec -i task-kanban-db psql -U kanban -d task_kanban

# 只停不删数据
docker compose --env-file .env -f docker/docker-compose.yml down
```

> 注意：`down -v` 会删掉 `task_kanban_pg_data` 卷，等于清库，别随手加 `-v`。

### 端口说明

| 服务 | 端口 | 是否对外 |
| --- | --- | --- |
| web (nginx) | 宿主机 `WEB_PORT` → 容器 80 | **对外** |
| api (NestJS) | 容器 3000 | 仅内网，由 nginx 反代 |
| db (postgres) | 容器 5432 | 仅内网 |

## 三、手工冒烟清单

每次部署后按顺序过一遍，全部通过即可交付使用。

### A. 登录与权限

- [ ] 打开 `http://<地址>:8080`，未登录时自动跳到登录页
- [ ] 用 `admin` 与 `ADMIN_INITIAL_PASSWORD` 登录成功
- [ ] 右上角能看到姓名与「管理员」标签；点「修改密码」能改密，改完需重新登录
- [ ] 成员管理页能新增成员（如 `lisi` / 李四 / 成员 / 初始密码）
- [ ] 用新成员账号登录，顶栏导航里**看不到**成员管理
- [ ] 成员试图编辑别人创建的任务 → 提示「只能修改自己创建或自己负责的任务」
- [ ] 成员试图删除别人创建的任务 → 提示「只有任务创建者或管理员可以删除任务」
- [ ] 管理员停用某成员后，该成员刷新页面被登出并提示账号失效

### B. 首页与项目

- [ ] 登录后落在**项目卡片墙**：卡片带渐变封面与右上角任务数徽章，末尾有「创建项目」虚线卡
- [ ] 顶栏导航有「项目 / 我的待办 / 成员管理」，当前页高亮；**没有左侧栏**
- [ ] 点左上角品牌名能回到卡片墙
- [ ] 点「创建项目」新建 `R25C14`，填开始日期与结束日期 → 卡片出现，状态「进行中」
- [ ] 重复建同名项目 → 提示项目名称已存在
- [ ] 卡片上的平均进度条与「完成率 x%（x/y）」正确
- [ ] 管理员把鼠标移到卡片封面左上角 → 出现「⋯」菜单，能编辑与删除
- [ ] 删除有任务的项目 → 弹窗提示「该项目下有 N 个任务」
- [ ] **点卡片进入该项目**，落在看板页，该项目全部任务都在
- [ ] 看板页里改任务 → 回到卡片墙，卡片进度跟着变

### C. 看板与任务

- [ ] 看板四列齐全：未开始 / 进行中 / 阻塞 / 已完成
- [ ] 顶部进度条与「完成率（x/y）」和各状态计数一致
- [ ] 新建任务（中文标题、负责人、参与人不乱码），默认落到「未开始」列末尾
- [ ] 新建弹窗里字段顺序是：标题 → 负责人 + 参与人（可多选）→ 优先级/状态/进度 → 计划开始/结束 → 实际开始/结束 → 描述，**没有「模块」和「截止日期」**
- [ ] 进度框只接受 0-100 整数：填 101 或 60.5 时应被拦下或提示
- [ ] 计划开始日期选得比计划结束日期晚时，弹窗给出提示
- [ ] 已填负责人后，参与人下拉里不再出现该负责人
- [ ] **把卡片从「未开始」拖到「已完成」→ 进度自动变 100%，并提示已完成**
- [ ] **再把卡片从「已完成」拖回「进行中」→ 进度仍是 100%（不清零）**
- [ ] 同一列内拖动排序，刷新页面后顺序保持不变
- [ ] 拖拽时顶部进度条与完成率同步变化
- [ ] 点卡片打开**居中详情弹窗**：顶部大标题 + 状态、四个字段块（负责人/参与人/优先级/进度）
- [ ] 弹窗左侧是描述、评论、操作日志；右侧固定栏是操作按钮与计划/实际日期、创建信息
- [ ] 在弹窗里发评论 → 评论立刻出现；右侧「编辑任务」能打开表单
- [ ] 三种入口都能打开该弹窗：看板卡片、任务列表标题、我的待办条目
- [ ] 在详情里发评论 → 评论立刻出现，操作日志多一条「发表了评论」
- [ ] 操作日志能看到状态变更记录（从 进行中 → 已完成）

### D. 任务列表

- [ ] 表格显示刚建的任务，列齐全
- [ ] 按负责人、参与人、优先级、状态分别筛选，结果正确
- [ ] 关键词搜索标题能命中
- [ ] 点表头按计划结束日期/优先级/进度排序
- [ ] 行内直接改状态、改负责人，保存后刷新仍生效
- [ ] 勾选多条 → 「批量修改」改优先级 → 提示已更新 N 条

### E. 导入导出

- [ ] 点「导出」下载 xlsx，用 Excel 打开中文正常、列齐全、含「填写说明」页
- [ ] 修改导出文件（改标题、加几行）后「导入」→ 预览表显示校验结果
- [ ] 故意留空标题的行 → 预览里该行标红「标题不能为空」，且不计入可导入数
- [ ] 负责人填一个不存在的名字 → 预览显示橙色警告并留空
- [ ] 确认导入 → 提示导入 N 条，看板出现新任务
- [ ] 状态列填「已完成」而进度填 30 → 导入后进度为 100%
- [ ] 参与人列填「李四、王五」→ 预览显示两个参与人；填一个不存在的名字 → 橙色警告且该名字被忽略
- [ ] 计划/实际日期列填 `2026/10/20` 这类写法也能识别

### F. 统计

- [ ] 统计页三个图表都有数据：状态分布、优先级分布、各负责人任务数与平均进度
- [ ] 新建/删除任务后回统计页刷新，图表数字跟着变

### G. 多人实时同步

- [ ] 用两个浏览器（或一个正常窗口 + 一个隐私窗口）分别用不同账号登录，都打开同一个项目的看板
- [ ] 顶部显示「实时同步中」
- [ ] A 新建一个任务 → B 的看板在 1 秒内自动出现该任务，并提示「XXX 新建了任务」
- [ ] C 是某任务的参与人，用 C 的账号能改这条任务，但不能删它
- [ ] A 拖拽卡片改状态 → B 的看板同步变化，进度条一起变
- [ ] 停掉后端再启动，前端能自动重连（标签回到「实时同步中」）

### H. 异常与边界

- [ ] 不登录直接访问 `http://<地址>:8080/#/projects` → 跳回登录页
- [ ] 删除项目时若项目下有任务 → 提示任务数并要求确认
- [ ] 用过期/伪造 token 调接口 → 401
- [ ] 上传非 xlsx 文件 → 提示解析失败，不是 500

## 四、排障

| 现象 | 排查方向 |
| --- | --- |
| 浏览器打不开 8080 | `docker compose ps` 看 web 是否 Up；`docker compose logs web` |
| 页面能开但接口全 502 | `docker compose logs api`，多半是迁移失败或 `DATABASE_URL` 错 |
| api 容器反复重启 | 看日志是否 `JWT_SECRET`/`POSTGRES_PASSWORD` 未设置（compose 会直接报错） |
| 实时同步显示「实时未连接」 | nginx 的 `/socket.io/` 是否配了 `Upgrade`/`Connection` 头；`docker compose logs web` |
| 看板操作提示 500 | `docker compose logs api`，常见是数据库未迁移完成 |
| 导入报「无法解析该文件」 | 只支持 `.xlsx`，老版 `.xls` 需要另存为 xlsx |
| 构建失败 | 确认 docker 与 compose 版本，`docker compose version` 是否 ≥ v2.3 |
