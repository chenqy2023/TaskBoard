## 一、总体定位

面向小团队的**项目与任务进度管理**看板，多人共用一套数据，不是单机页面。

| 维度 | 结论 |
| --- | --- |
| 使用形态 | 多人访问的 Web 系统 |
| 后端 | TypeScript + NestJS + Prisma |
| 前端 | TypeScript + Vue3 + Vite + Ant Design Vue + Pinia |
| 数据库 | PostgreSQL 16-alpine |
| 部署 | 生产：Linux 服务器上用 docker compose（nginx + api + postgres 三服务）<br>开发：本机用 Docker 起数据库，前后端用 node 直接跑 |
| 镜像来源 | 直连官方镜像，镜像名/标签可在 `.env` 覆盖，便于以后切私有仓库 |
| 界面语言 | 中文 |
| 时区 | 展示用 `Asia/Shanghai`，库内统一存 UTC |

## 二、业务模型

**两层结构：项目 → 任务**，任务是最小工作单位（不做用例库）。

- 项目（Project）：项目名称唯一，带开始日期、结束日期、状态（进行中／已完成／已归档）。
- 任务（Task）：归属某个项目，含标题、负责人、参与人（多选）、优先级、状态、进度、计划与实际四个日期、描述。
- 任务下挂评论与操作日志。

### 看板列（状态流转）

四列固定：**未开始 → 进行中 → 阻塞 → 已完成**

### 进度口径

- 任务进度由负责人**手动填写百分比**，只接受 0-100 的整数（输入框，不接受小数与越界值）。
- 项目进度 = 该项目全部未删除任务进度的**算术平均**（四舍五入为整数）。
- 同时展示**任务完成率** = 已完成任务数 / 总任务数（保留 1 位小数）。
- 两个口径并排显示，互相印证。

### 任务上的日期

四个日期，都是可选的：

| 字段 | 说明 |
| --- | --- |
| 计划开始日期 | 计划何时开始测 |
| 计划结束日期 | 计划何时测完。**逾期判断以它为准** |
| 实际开始日期 | 实际何时开始 |
| 实际结束日期 | 实际何时结束 |

**逾期** = 未完成 且 计划结束日期已过。计划开始晚于计划结束、实际开始晚于实际结束时会给出提示，但不拦截保存。

### 状态与进度的联动规则

| 操作 | 结果 |
| --- | --- |
| 拖到「已完成」 | 进度自动置 100%，记录完成时间 |
| 拖出「已完成」 | 保留原进度不清零，清空完成时间 |
| 手动把进度改成 100% | **不会**自动移动到「已完成」列（避免误操作） |

### 优先级、参与人与负责人

- 优先级固定四档，界面上只显示**紧急 / 高 / 中 / 低**四个描述，不出现 P0~P3 编号
  （数据库枚举内部仍是 P0~P3，接口与 Excel 导入也仍兼容 `P0`、`P0 紧急` 这类旧写法，老文件能原样导回）。
- 负责人只有一个，可为空（未分配）。
- 参与人可以有多个，用于记录一起做这条任务的人；填了负责人之后，参与人下拉里不再重复出现该负责人。
- **没有「模块」字段**（首版曾有，已按需求移除，筛选与统计里对应维度也一并去掉）。

## 三、权限

账号密码登录（JWT），两种角色：

| 角色 | 能力 |
| --- | --- |
| 管理员 ADMIN | 管理成员、删除项目、删除任意任务、修改任意任务 |
| 成员 MEMBER | 新建任务；修改自己创建、自己负责或自己参与的任务；不能删他人任务；不能进成员管理 |

补充约束：

- 管理员不能改自己的角色、不能停用或删除自己的账号。
- 系统必须始终保留至少一个启用的管理员。
- 成员可以查看全部项目与任务（看板对全员开放）。

## 四、功能范围

第一版包含：

1. 登录 / 登出 / 修改密码，成员管理（管理员）
2. 项目管理：列表、新建、编辑、归档、删除，每行显示进度条
3. 看板：四列拖拽改状态、列内排序、新建/编辑/删除任务
4. 任务列表：表格视图、多条件筛选、排序、分页、行内改状态与负责人、批量修改
5. 评论 + 操作日志时间线
6. ECharts 统计：状态分布、优先级分布、各负责人任务数与平均进度
7. Excel（`.xlsx`）批量导入导出（导入先预览校验再落库；不支持老版 `.xls` 与 CSV）
8. 多人实时同步（Socket.IO 推送，看板自动刷新）

明确不做：

- 附件上传（明确不做，因此也不需要对象存储和上传目录）
- 移动端适配（只保证桌面端 ≥1280px）
- 第三方登录、消息通知推送

## 五、交付节奏

分两阶段，先后核心再加分项：

- 阶段一（核心链路）：登录 → 项目 → 看板拖拽 → 进度汇总 → 任务列表筛选。可本地完整演示并验收。
- 阶段二（加分项）：评论/日志、统计图表、Excel 导入导出、实时同步。
- 阶段三（生产交付）：生产 compose、nginx 反代、关键单测、部署与冒烟文档。

## 六、测试要求

- 后端关键逻辑写单元测试（进度汇总、状态与进度联动、权限规则、导入行校验）。
- 不写 Playwright E2E，交付一份**手工冒烟清单**（见「部署与冒烟清单」）。
- 另提供接口级冒烟脚本 `scripts/api-smoke.py`，一条命令跑完 37 项检查。

## 七、开工时定下的默认决定

以下为实现方按「不惊吓用户 / 少配置」原则定的默认值，如不认可可以改：

1. 初始管理员账号密码由 `ADMIN_INITIAL_PASSWORD` 环境变量注入，仅在库中无用户时创建。
2. JWT 有效期 7 天，token 存 localStorage（便于开发期调试）。
3. 任务删除为**软删除**（`deletedAt`），操作日志与评论保留可追溯；项目删除为硬删除，且当项目下还有任务时必须显式带 `force=true`。
4. 操作日志自动记录：创建/删除任务、状态变更、负责人变更、参与人变更、优先级变更、四种日期变更、新增评论；**进度变动小于 5% 不记日志**，避免拖进度条刷满时间线。
5. Excel 列名固定为「标题/负责人/参与人/优先级/状态/进度/计划开始日期/计划结束日期/实际开始日期/实际结束日期/描述」，并容忍一些常见别名（如「任务标题」「指派给」「截止日期」「计划完成日期」「备注」）。
